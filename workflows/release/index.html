    Release¶

    Release handling spans four workflows and one Probot configuration.

    • reusable-release-drafter.yml maintains the draft release with a generated changelog as PRs land.
    • reusable-release-drafter-autolabel.yml applies the type label from each pull request's title and removes the type labels the title no longer implies, so the changelog files it under one category.
    • reusable-release-publish.yml promotes the open draft to a published release for a given tag, with an optional dry-run validation gate.
    • reusable-release-cd-refresh-master.yml points the presentation branch at the published release tag, so it always tracks the latest release. It reads the target's protection and picks the write strategy from it: a merge commit where merge commits are permitted, a force-with-lease reset where they aren't, and a loud refusal where the target permits neither. See ADR-001.
    • _extends: gh-plumbing:.github/commons-release-drafter.yml provides shared release-drafter categorization.

    Categorization

    Release-drafter buckets PRs by label. commons-settings declares the shared label palette, and boring-cyborg applies the labels to each PR.

    Type labels on pull requests¶

    The categories match type labels only: feat, fix, chore, docs. The autolabeler: block in the shared configuration derives that label from the Conventional-Commits title. release-drafter runs it only on pull-request events, never on the push that updates the draft. Without the workflow below, a pull request merged without a hand-applied type label lands under no category.

    release-drafter only ever adds labels. When a title changes type, for example from feat: to fix:, the old label would stay and the changelog would list the pull request twice. So once release-drafter has run, the reusable removes every other type label from the pull request. A title that implies no type label, such as refactor:, ci:, or free text, removes nothing, so a label set by hand stays. Other labels, such as documentation, release, or experimental, are never removed. If the pull request lacks the label its title implies, the step logs that and removes nothing. That's the normal case for a repository whose own release-drafter configuration uses other label names. A repository whose configuration assigns feat, fix, chore, or docs by file path or branch loses that label when the title implies a different one and the pull request carries it. Removing a label needs no extra permission: pull-requests: write covers it.

    .github/workflows/release-drafter-autolabel.yml
    on:
  pull_request_target:
    types: [opened, reopened, edited]

permissions:
  contents: read

jobs:
  autolabel:
    permissions:
      contents: read
      pull-requests: write
    uses: nolte/gh-plumbing/.github/workflows/reusable-release-drafter-autolabel.yml@<tag>
    secrets:
      token: ${{ secrets.GITHUB_TOKEN }}

    Why pull_request_target

    Under pull_request, a fork pull request gets a read-only token and the label write fails. The reusable checks out nothing and reads only metadata, such as the title and branch name. No code from the pull request runs with the write token. Don't add a checkout of the pull request head to it.

    Area labels aren't categories

    boring-cyborg labels such as documentation or cicd describe where a pull request changed something. A category that matched one listed the pull request a second time, next to its type. A pre-commit hook in this repository refuses that combination.

    Publish a release¶

    .github/workflows/release-publish.yml
    on:
  workflow_dispatch:
    inputs:
      tag:
        description: "Tag to publish (must match an open release-drafter draft)."
        required: true
        type: string
      dry_run:
        description: "Validate without flipping draft=false."
        required: false
        type: boolean
        default: false

jobs:
  publish:
    uses: nolte/gh-plumbing/.github/workflows/reusable-release-publish.yml@<tag>
    with:
      tag: ${{ inputs.tag }}
      dry_run: ${{ inputs.dry_run }}
    secrets:
      token: ${{ secrets.GITHUB_TOKEN }}

    Tag must match an existing draft

    tag must match the tag on an existing release-drafter draft. There is no "newest wins" heuristic—if no draft exists for the given tag the workflow fails fast. Run the draft workflow on develop first.

    Attach a built archive before publish

    To ship a Task-built archive with build provenance, run reusable-release-archive.yml ahead of this workflow and order the publish job after it with needs:. Pass the archive's target-sha output as expected-target-sha. The workflow then refuses to publish when the draft target is no longer the commit the archive came from. It also refuses the input together with auto-align: true.

    Input Default Effect
    expected-target-sha empty Full commit SHA the draft target must equal; the workflow pins the target to it before publishing

    Dry run

    Set dry_run: true to run every validation gate without flipping the draft to a published release. Useful for verifying the publish path before the actual release.

    Publishing refuses when the cascade can't run

    Before the flip, the workflow checks that release-cd-refresh-master.yml exists and is active. A release published into a dead cascade leaves the presentation branch stale behind a green run, which is how v2.0.0 went unnoticed here for six weeks.

    A repository that deliberately keeps no presentation branch sets require-cascade: false. The gate still refuses when the workflow exists and is switched off, because a cascade that's present and disabled is a different fact from one nobody wanted.

    Input Default Effect
    require-cascade true Require the cascade workflow to exist and be active before publishing

    Don't commit to master directly—the workflow will overwrite your changes on the next release.

# release-drafter rewrites the whole draft body, so this reusable brackets the
# call with a capture/restore of the project-context block (see the `jobs:`
# below). That read-modify-write is not atomic: two pushes to develop in quick
# succession would interleave and one run would overwrite the other's restored
# block, silently shipping release notes with a section missing. Serialise per
# ref so the sequence runs to completion.
#
# cancel-in-progress stays false: cancelling mid-sequence is what would leave
# the draft body in the half-written state this group exists to prevent.
concurrency:
  group: release-drafter-${{ github.ref }}
  cancel-in-progress: false


jobs:
  update_release_draft:
    permissions:
      contents: write # a release draft is a contents-scope object
      pull-requests: read # release-drafter categorises merged PRs into the changelog
    name: Update Release Draft
    runs-on: ubuntu-latest
    steps:
      # Mint an App installation token only when the caller has set
      # inputs.app-id. The output token (when present) replaces
      # secrets.token everywhere downstream in this job via the
      # steps.app-token.outputs.token || secrets.token fallback.
      - name: Mint App installation token
        id: app-token
        if: ${{ inputs.app-id != '' }}
        # Tolerate a half-configured setup. On any failure outputs.token
        # is empty and the fallback to secrets.token kicks in — release-
        # drafter keeps working under GITHUB_TOKEN, only the audit-trail
        # consistency is lost.
        continue-on-error: true
        uses: actions/create-github-app-token@fee1f7d63c2ff003460e3d139729b119787bc349 # v2.2.2
        with:
          app-id: ${{ inputs.app-id }}
          private-key: ${{ secrets.app-private-key }}

      # Capture the release-skill-layer project-context block from the current
      # open draft, if any, before release-drafter regenerates the body.
      # release-drafter@v6 fully rewrites the body from its template, so any
      # content owned by other tooling (here: nolte-shared release-notes-curate)
      # is otherwise lost. Spec reference: spec/project/release-skill-layer/
      # §Skill A — Draft notes curation.
      - name: Capture project-context block
        id: capture
        env:
          GH_TOKEN: ${{ steps.app-token.outputs.token || secrets.token }}
          REPO: ${{ github.repository }}
        run: |
          set -euo pipefail
          # Masks $1 for a log line (#492): control characters become '?' and
          # '##[' becomes '#?[', so the value can neither end the line nor open
          # the runner's older '##[command]' syntax in the middle of one.
          shown() { local v="${1//[[:cntrl:]]/?}"; printf '%s' "${v//\#\#\[/#?[}"; }
          start_marker='<!-- release-skill-layer:project-context-start -->'
          end_marker='<!-- release-skill-layer:project-context-end -->'

          # gh release list on the runner CLI does not expose targetCommitish;
          # we only need tagName here, the restore step re-resolves the active draft.
          draft=$(gh release list --repo "$REPO" \
            --json isDraft,tagName \
            --jq '[.[] | select(.isDraft == true)] | .[0]')

          if [[ -z "$draft" || "$draft" == "null" ]]; then
            echo "No existing draft to capture from."
            echo "had_markers=false" >> "$GITHUB_OUTPUT"
            exit 0
          fi

          captured_tag=$(echo "$draft" | jq -r '.tagName')
          # A draft's tag name is editable text, and the restore step reads it
          # from this step's output. A line end in it could start a workflow
          # command in the messages below or add an entry to $GITHUB_OUTPUT,
          # and '##[' opens the runner's older command syntax anywhere in a log
          # line. Such a draft is skipped like the other unusable ones here,
          # before the first message that prints the tag, so no later
          # '$captured_tag' carries either (#492).
          #
          # Git refuses ASCII control characters, DEL and '[' in a ref name.
          # The control-character rule is deliberately wider: in a UTF-8 locale
          # [[:cntrl:]] also matches C1 (U+0080-U+009F) and U+2028/U+2029,
          # which git allows -- see the tag check in "Resolve draft" of
          # reusable-release-publish.yml for why and what the runner source
          # shows.
          if [[ "$captured_tag" == *[[:cntrl:]]* || "$captured_tag" == *'##['* ]]; then
            echo "::warning::Draft tag '$(shown "$captured_tag")' contains a control character or '##[' (shown as '?' and '#?['); not capturing its project-context block."
            echo "had_markers=false" >> "$GITHUB_OUTPUT"
            exit 0
          fi
          body=$(gh release view "$captured_tag" --repo "$REPO" --json body --jq .body)

          if ! grep -qF "$start_marker" <<< "$body" || ! grep -qF "$end_marker" <<< "$body"; then
            echo "Draft '$captured_tag' has no project-context marker pair."
            echo "had_markers=false" >> "$GITHUB_OUTPUT"
            exit 0
          fi

          captured=$(awk -v s="$start_marker" -v e="$end_marker" '
            BEGIN { p=0 }
            index($0, s) > 0 { p=1 }
            p { print }
            index($0, e) > 0 { p=0 }
          ' <<< "$body")

          if [[ -z "$captured" ]]; then
            echo "::warning::Marker pair present but extraction returned empty — skipping restore."
            echo "had_markers=false" >> "$GITHUB_OUTPUT"
            exit 0
          fi

          mkdir -p .release-drafter-cache
          printf '%s\n' "$captured" > .release-drafter-cache/markers.md
          echo "had_markers=true" >> "$GITHUB_OUTPUT"
          echo "captured_tag=$captured_tag" >> "$GITHUB_OUTPUT"
          echo "Captured marker block from draft '$captured_tag' ($(wc -l < .release-drafter-cache/markers.md) lines)."

      - name: Update Release Draft
        uses: release-drafter/release-drafter@6a93d829887aa2e0748befe2e808c66c0ec6e4c7 # v6.4.0
        env:
          GITHUB_TOKEN: ${{ steps.app-token.outputs.token || secrets.token }}

      - name: Restore project-context block
        if: steps.capture.outputs.had_markers == 'true'
        env:
          GH_TOKEN: ${{ steps.app-token.outputs.token || secrets.token }}
          REPO: ${{ github.repository }}
          CAPTURED_TAG: ${{ steps.capture.outputs.captured_tag }}
        run: |
          set -euo pipefail
          # Masks $1 for a log line (#492): control characters become '?' and
          # '##[' becomes '#?[', so the value can neither end the line nor open
          # the runner's older '##[command]' syntax in the middle of one.
          shown() { local v="${1//[[:cntrl:]]/?}"; printf '%s' "${v//\#\#\[/#?[}"; }
          start_marker='<!-- release-skill-layer:project-context-start -->'
          end_marker='<!-- release-skill-layer:project-context-end -->'

          draft=$(gh release list --repo "$REPO" \
            --json isDraft,tagName \
            --jq '[.[] | select(.isDraft == true)] | .[0]')

          if [[ -z "$draft" || "$draft" == "null" ]]; then
            echo "::warning::No draft after release-drafter run — markers not restored."
            exit 0
          fi

          new_tag=$(echo "$draft" | jq -r '.tagName')

          if [[ "$new_tag" != "$CAPTURED_TAG" ]]; then
            # new_tag is a draft's tag name, not yet checked: masked (#492).
            echo "::warning::Draft tag changed from '$CAPTURED_TAG' to '$(shown "$new_tag")' — captured markers may be stale; not restoring. Re-run release-notes-curate to regenerate the project-context block."
            exit 0
          fi

          current_body=$(gh release view "$new_tag" --repo "$REPO" --json body --jq .body)

          if grep -qF "$start_marker" <<< "$current_body" && grep -qF "$end_marker" <<< "$current_body"; then
            echo "Marker pair already present in post-drafter body. release-drafter@v6 preserved it; skipping restore."
            exit 0
          fi

          captured=$(cat .release-drafter-cache/markers.md)
          new_body=$(printf '%s\n\n%s' "$current_body" "$captured")

          tmpfile=$(mktemp)
          printf '%s' "$new_body" > "$tmpfile"
          gh release edit "$new_tag" --repo "$REPO" --notes-file "$tmpfile"
          rm -f "$tmpfile"

          echo "::notice::Restored release-skill-layer project-context block to draft '$new_tag'."

jobs:
  publish:
    name: Publish Release
    runs-on: ubuntu-latest
    permissions:
      contents: write # flips the release draft to published
    steps:
      # Mint an App installation token only when the caller has set
      # inputs.app-id. The output token (when present) replaces
      # secrets.token everywhere downstream in this job via the
      # steps.app-token.outputs.token || secrets.token fallback.
      - name: Mint App installation token
        id: app-token
        if: ${{ inputs.app-id != '' }}
        # Tolerate a half-configured setup. On any failure outputs.token
        # is empty and the fallback to secrets.token kicks in — release-
        # publish keeps working, the cascade gap returns silently.
        continue-on-error: true
        uses: actions/create-github-app-token@fee1f7d63c2ff003460e3d139729b119787bc349 # v2.2.2
        with:
          app-id: ${{ inputs.app-id }}
          private-key: ${{ secrets.app-private-key }}

      - name: Checkout develop
        uses: actions/checkout@d23441a48e516b6c34aea4fa41551a30e30af803 # v6.1.0
        with:
          ref: develop
          fetch-depth: 0
          token: ${{ steps.app-token.outputs.token || secrets.token }}
          # Kept: the "Align version-bearing files (primary path)" step
          # runs `git push origin HEAD:develop` with this credential.
          persist-credentials: true

      - name: Resolve draft
        id: draft
        env:
          GH_TOKEN: ${{ steps.app-token.outputs.token || secrets.token }}
          REQUESTED_TAG: ${{ inputs.tag }}
        run: |
          set -euo pipefail
          # Masks $1 for a log line (#492): control characters become '?' and
          # '##[' becomes '#?[', so the value can neither end the line nor open
          # the runner's older '##[command]' syntax in the middle of one.
          shown() { local v="${1//[[:cntrl:]]/?}"; printf '%s' "${v//\#\#\[/#?[}"; }
          # gh release list on the runner CLI does not expose targetCommitish;
          # resolve the target via gh release view per matching tag.
          drafts=$(gh release list --json isDraft,tagName --jq '[.[] | select(.isDraft == true)]')
          total=$(echo "$drafts" | jq 'length')

          if [[ "$total" == "0" ]]; then
            echo "::error::No draft release found. Run release-drafter.yml on develop first."
            exit 1
          fi

          if [[ -z "$REQUESTED_TAG" ]]; then
            # Omitted tag: exactly one candidate, or an error naming every one
            # of them. Never "newest wins" -- picking silently is how a release
            # gets published from a draft nobody was looking at.
            if [[ "$total" != "1" ]]; then
              echo "::error::No tag given and $total drafts are open. Pass 'tag' explicitly. Open drafts:"
              # Draft tag names are editable text, listed with control
              # characters masked as in the target messages below (#492).
              echo "$drafts" | jq -r '.[] | "  - \(.tagName | gsub("[[:cntrl:]]"; "?") | gsub("##\\["; "#?["))"' >&2
              exit 1
            fi
            TAG=$(echo "$drafts" | jq -r '.[0].tagName')
          else
            TAG="$REQUESTED_TAG"
          fi

          # The tag is the caller's input or a draft's tag name, and every later
          # step reads it from this step's output. A line end in it could start a
          # workflow command in any message that prints the tag or add an entry
          # to $GITHUB_OUTPUT, and '##[' opens the runner's older command syntax
          # anywhere in a log line (ActionCommand.TryParse in actions/runner,
          # read from source, not measured on a runner). Both are refused here,
          # before the first message that prints the tag and before the output
          # write, so no later '$TAG' carries either (#492). Only this message
          # shows it, masked.
          #
          # Git refuses ASCII control characters, DEL and '[' in a ref name, so
          # the '##[' rule costs no tag git accepts. The control-character rule
          # is deliberately wider in a UTF-8 locale, where [[:cntrl:]] also
          # matches C1 (U+0080-U+009F) and U+2028/U+2029, which git allows; in
          # the C locale it matches neither. Which locale the runner gives this
          # step was not verified. LF and CR -- what the runner's line
          # splitting needs -- match in every locale, as do ESC and DEL. Read
          # from actions/runner, not measured on a runner: step output is split
          # into lines by StreamReader.ReadLine, at LF, CR and CRLF only
          # (ProcessInvoker.cs), and $GITHUB_OUTPUT at LF (FileCommandManager.cs),
          # so neither C1 nor U+2028/U+2029 ends a line there. A tag carrying
          # one is refused all the same, although git would accept it. Locale behaviour
          # measured with (prints "cntrl"; the same with \u2028, nothing under
          # LC_ALL=C):

              selector with optional `[]`/`[*]` array wildcards. Raises
              KeyError/TypeError/IndexError on a path that does not resolve."""
              parts = [p for p in selector.split(".") if p]
              nodes = [data]
              for i, raw in enumerate(parts):
                  if raw.endswith("[]"):
                      key, wild = raw[:-2], True
                  elif raw.endswith("[*]"):
                      key, wild = raw[:-3], True
                  else:
                      key, wild = raw, False
                  last = i == len(parts) - 1
                  nxt = []
                  for n in nodes:
                      child = n[key]
                      if wild:
                          if not isinstance(child, list):
                              raise TypeError(f"selector part '{raw}' is not an array")

                              nxt.extend((child, idx) for idx in range(len(child)))
                          else:
                              nxt.extend(child)
                      else:

                  nodes = nxt
              return nodes

      # is still a draft. `gh release edit --draft=false` (and any automerge-style
      # wrapper around it) can exit 0 without the draft actually flipping — the
      # silent-success footgun #375 names. Never trust the publish step's exit
      # code alone; verify the observable state.
      - name: Post-publish sanity
        if: ${{ inputs.dry_run != true }}
        env:
          GH_TOKEN: ${{ steps.app-token.outputs.token || secrets.token }}
          TAG: ${{ steps.draft.outputs.tag }}
        run: |
          set -euo pipefail
          is_draft=$(gh release view "$TAG" --json isDraft --jq .isDraft)
          if [[ "$is_draft" != "false" ]]; then
            echo "::error::Post-publish check failed: '$TAG' still reports isDraft=$is_draft after the flip (expected false). The publish step exited 0 but the draft did not flip — re-run release-publish or flip the draft manually (gh release edit '$TAG' --draft=false)."
            exit 1
          fi
          echo "Post-publish: isDraft=false confirmed."

      # Pitfall 2: deterministic cascade-gap warning bound to the fallback
      # condition itself. steps.app-token.outputs.token is empty in exactly the
      # two cases the issue names — inputs.app-id unset (mint step skipped) or
      # the App-token mint failed (continue-on-error) — so this fires precisely
      # when the release:published event was authored by GITHUB_TOKEN and will
      # NOT cascade. Surfaced in the job summary, not just the log.
      - name: Warn on GITHUB_TOKEN cascade gap
        if: ${{ inputs.dry_run != true && steps.app-token.outputs.token == '' }}
        run: |
          set -euo pipefail
          msg="Published under GITHUB_TOKEN (no portfolio App token: inputs.app-id unset or the App-token mint failed).           echo "::warning::$msg"
          {
            echo
            echo "### ⚠️ Cascade gap (GITHUB_TOKEN fallback)"
            echo
            echo "$msg"
          } >> "$GITHUB_STEP_SUMMARY"

      # the cascade is therefore expected to fire. Gating on token != '' keeps
      # this neutral/informational note from contradicting the deterministic
      # cascade-gap warning above (the two conditions are mutually exclusive).
      - name: Probe cascade run (App token path)
        if: ${{ inputs.dry_run != true && steps.app-token.outputs.token != '' }}
        env:
          GH_TOKEN: ${{ steps.app-token.outputs.token || secrets.token }}
          TARGET_SHA: ${{ steps.align.outputs.target_sha || steps.draft.outputs.target_sha }}

          set -euo pipefail
          # Masks $1 for a log line (#492): control characters become '?' and
          # '##[' becomes '#?[', so the value can neither end the line nor open
          # the runner's older '##[command]' syntax in the middle of one.
          shown() { local v="${1//[[:cntrl:]]/?}"; printf '%s' "${v//\#\#\[/#?[}"; }

          # probe, never an error (spec/project/workflow-health/ §Known platform constraints).
          sleep 30
          refresh_run=$(gh run list --workflow=release-cd-refresh-master.yml --limit 1 --json status,createdAt,headSha --jq '.[0]')

          else
            # An API response, one line of JSON; masked like the others (#492).
            echo "release-cd-refresh-master.yml run detected: $(shown "$refresh_run")"
          fi

# Every run of this workflow updates the same presentation branch, so two
# releases published close together race on one target. The group is static
# rather than ref-derived on purpose: the contended resource is the target
# branch, not the ref that triggered the run, and two runs from different tags
# still collide. Matches the `release-publish` group in
# reusable-release-publish.yml.
#
# cancel-in-progress stays false per spec/project/github-actions-best-practices
# §F: a delivery workflow must never cancel an in-flight run.
concurrency:
  group: release-cd-refresh-master
  cancel-in-progress: false


jobs:
  refresh_presentation_branch:
    permissions:
      contents: write # fast-forwards the presentation branch
    name: "Publish the the Release to Master"
    runs-on: ubuntu-latest
    steps:
      # Mint an App installation token only when the caller has set
      # inputs.app-id. The output token replaces secrets.token for the
      # checkout and the push via the
      # `steps.app-token.outputs.token || secrets.token` fallback.
      - name: Mint App installation token
        id: app-token
        if: ${{ inputs.app-id != '' }}
        # Tolerate a half-configured setup. On any failure outputs.token
        # is empty and the fallback to secrets.token kicks in — note
        # that on a protected master with `restrictions.apps`, the
        # fallback will fail at push time; the operator must complete
        # Phase 0 (variable + secret) before this workflow can
        # succeed on a fully-restricted master.
        continue-on-error: true
        uses: actions/create-github-app-token@fee1f7d63c2ff003460e3d139729b119787bc349 # v2.2.2
        with:
          app-id: ${{ inputs.app-id }}
          private-key: ${{ secrets.app-private-key }}

      - name: Checkout
        uses: actions/checkout@d23441a48e516b6c34aea4fa41551a30e30af803 # v6.1.0
        with:
          # Full history plus tags: the reset resolves an arbitrary ref to a
          # commit, which a shallow clone cannot do.
          fetch-depth: 0
          token: ${{ steps.app-token.outputs.token || secrets.token }}
          # Kept: the "Refresh the presentation branch" step runs
          # `git fetch`, `git ls-remote` and `git push` against origin.
          persist-credentials: true

      # A single write strategy cannot serve every presentation branch, because
      # real consumer configurations forbid opposite things (issue #414):
      #
      #   linear history  -> no merge commits  -> the merge is rejected
      #   no force pushes -> no rewrite        -> the reset is rejected
      #
      # ADR-001 chose the reset to solve the first and did not consider the
      # second. `gh-plumbing`'s own master is the second case, which is why
      # v2.0.0 and v2.0.1 both published green while master stayed on v1.1.26.
      #
      # So the strategy is read from the target rather than assumed. Both
      # mechanisms have to be consulted -- classic protection and rulesets are
      # independent, and either can forbid either operation.
      - name: Determine the write strategy from the target's protection
        id: strategy
        env:
          GH_TOKEN: ${{ steps.app-token.outputs.token || secrets.token }}
          TARGET: ${{ inputs.target_branch }}
        run: |
          set -euo pipefail
          # Masks $1 for a log line (#492): control characters become '?' and
          # '##[' becomes '#?[', so the value can neither end the line nor open
          # the runner's older '##[command]' syntax in the middle of one.
          shown() { local v="${1//[[:cntrl:]]/?}"; printf '%s' "${v//\#\#\[/#?[}"; }

          # An unreadable endpoint must not read as "unrestricted": that is the
          # mistake the branch-protection audit made (#421). Unknown means the
          # restriction is assumed to be present, so the run degrades to a
          # refusal with a diagnosis rather than a rejected push.
          classic=$(gh api "repos/${GITHUB_REPOSITORY}/branches/${TARGET}/protection" 2>/dev/null || echo '')
          rules=$(gh api "repos/${GITHUB_REPOSITORY}/rules/branches/${TARGET}" 2>/dev/null || echo '[]')

          rule_types=$(echo "$rules" | jq -r '[.[]?.type] | unique | join(",")')

          # `pull_request` blocks every direct write, merge and reset alike.
          blocks_direct=$(echo "$rules" | jq -r 'any(.[]?; .type == "pull_request")')
          # Force push: classic `allow_force_pushes`, and the `non_fast_forward`
          # rule which forbids any history rewrite.
          rule_no_force=$(echo "$rules" | jq -r 'any(.[]?; .type == "non_fast_forward")')
          classic_force=$(echo "${classic:-{\}}" | jq -r '.allow_force_pushes.enabled // false')
          # Merge commits: classic and ruleset linear-history both forbid them.
          rule_linear=$(echo "$rules" | jq -r 'any(.[]?; .type == "required_linear_history")')
          classic_linear=$(echo "${classic:-{\}}" | jq -r '.required_linear_history.enabled // false')

          force_ok=false
          [ "$classic_force" = "true" ] && [ "$rule_no_force" != "true" ] && force_ok=true
          merge_ok=false
          [ "$classic_linear" != "true" ] && [ "$rule_linear" != "true" ] && merge_ok=true

          if [ "$blocks_direct" = "true" ]; then
            mode=blocked
            reason="a \`pull_request\` ruleset rule requires every change to arrive through a pull request, so neither a merge nor a reset may be pushed directly"
          elif [ "$merge_ok" = "true" ]; then
            # Preferred over the reset when both are available: it adds to the
            # branch instead of rewriting it, so a consumer holding anything on
            # the presentation branch does not lose it.
            mode=merge
            reason="merge commits are permitted"
          elif [ "$force_ok" = "true" ]; then
            mode=reset
            reason="merge commits are forbidden, force pushes are permitted"
          else
            mode=blocked
            reason="the target forbids merge commits and force pushes alike"
          fi

          {
            echo "mode=$mode"
            echo "reason=$reason"
          } >> "$GITHUB_OUTPUT"
          # target_branch and from_branch are caller input. This job's own log
          # messages print them through shown() (#492), the step summaries
          # below through md_code() (#506); git's own output prints them as
          # they are.
          echo "Strategy for '$(shown "$TARGET")': ${mode} -- ${reason}"
          echo "  classic protection readable: $([ -n "$classic" ] && echo yes || echo 'no (absent or unreadable)')"
          echo "  ruleset rules: ${rule_types:-(none)}"

      - name: Refresh the presentation branch
        id: refresh
        if: steps.strategy.outputs.mode != 'blocked'
        env:
          GH_TOKEN: ${{ steps.app-token.outputs.token || secrets.token }}
          FROM_REF: ${{ inputs.from_branch }}
          TARGET: ${{ inputs.target_branch }}
          MODE: ${{ steps.strategy.outputs.mode }}
        run: |
          set -euo pipefail
          # Masks $1 for a log line (#492): control characters become '?' and
          # '##[' becomes '#?[', so the value can neither end the line nor open
          # the runner's older '##[command]' syntax in the middle of one.
          shown() { local v="${1//[[:cntrl:]]/?}"; printf '%s' "${v//\#\#\[/#?[}"; }
          # Encode, then wrap, for the step summary (#506): a control character
          # becomes a question mark and an ASCII punctuation character its
          # numeric HTML entity (`@` also gets an empty comment after it, so no
          # e-mail autolink forms), inside <code> (md_code) or <pre> (md_pre,
          # line ends kept). Caller and repository text then renders as
          # text and links nothing.
          md_enc() { local LC_ALL=C; local s="${1//[[:cntrl:]]/?}" c n x; s="${s//$'\xc2'[$'\x80'-$'\x9f']/?}"; s="${s//$'\xe2\x80'[$'\xa8\xa9']/?}"; for n in {33..47} {58..64} {91..96} {123..126}; do printf -v x '%x' "$n"; printf -v c '%b' "\\x$x"; s=${s//"$c"/$'\x01'$n$'\x02'}; done; s=${s//$'\x01'64$'\x02'/$'\x01'64$'\x02\x03'}; s=${s//$'\x01'/'&#'}; s=${s//$'\x02'/';'}; s=${s//$'\x03'/'<!-- -->'}; printf '%s' "$s"; }
          md_code() { printf '<code>%s</code>' "$(md_enc "$1")"; }
          md_pre() { local line; printf '<pre>'; while IFS= read -r line; do md_enc "${line%$'\r'}"; printf '\n'; done <<< "$1"; printf '</pre>\n'; }

          # Fail loudly rather than defaulting. An empty ref is what made the
          # old behaviour wrong-but-green for every release so far.
          if [ -z "${FROM_REF}" ]; then
            echo "::error::from_branch resolved to an empty value. On a release" \
                 "trigger it defaults to github.event.release.tag_name; on a" \
                 "manual run, pass the tag explicitly." >&2
            exit 1
          fi

          git fetch --force --tags --prune origin

          # Accept a tag, a branch or a raw SHA, in that order of preference.
          SOURCE_SHA="$(
            git rev-parse --verify --quiet "refs/tags/${FROM_REF}^{commit}" ||
            git rev-parse --verify --quiet "refs/remotes/origin/${FROM_REF}^{commit}" ||
            git rev-parse --verify --quiet "${FROM_REF}^{commit}"
          )" || {
            # from_branch is caller input or a release tag name; masked like
            # the target (#492).
            echo "::error::Could not resolve '$(shown "$FROM_REF")' to a commit." >&2
            exit 1
          }

          EXPECTED="$(git ls-remote origin "refs/heads/${TARGET}" | awk '{print $1}')"

          if [ -z "${EXPECTED}" ]; then
            echo "Target branch '$(shown "$TARGET")' does not exist yet; creating it."
            git push origin "${SOURCE_SHA}:refs/heads/${TARGET}"
            action="created"
          elif [ "${EXPECTED}" = "${SOURCE_SHA}" ]; then
            echo "Target branch '$(shown "$TARGET")' already points at ${SOURCE_SHA}; nothing to do."
            action="already current"
          elif [ "${MODE}" = "merge" ]; then
            # The /merges API, the mechanism that worked before #404 and still
            # works wherever merge commits are allowed. It is additive, so the
            # target keeps whatever it already carries.
            if ! out=$(gh api "repos/${GITHUB_REPOSITORY}/merges" \
                         -f base="${TARGET}" -f head="${SOURCE_SHA}" \
                         -f commit_message="chore(release): refresh ${TARGET} to ${FROM_REF}" 2>&1); then
              # The response is API text and the refs are caller input; all
              # three are masked (#492).
              echo "::error::Merging $(shown "$FROM_REF") into '$(shown "$TARGET")' failed even though the target reports that merge commits are permitted. The protection may have changed since the check, or the token may lack write access. Response: $(shown "$out")" >&2
              exit 1
            fi
            action="merged"
          else
            # --force-with-lease, not --force: if another run advanced the
            # target between the read above and this push, the push aborts
            # instead of discarding that run's work. The concurrency group on
            # this workflow makes that unlikely; the lease makes it safe.
            git push --force-with-lease="${TARGET}:${EXPECTED}" \
              origin "${SOURCE_SHA}:refs/heads/${TARGET}"
            action="reset"
          fi

          previous="${EXPECTED:-<branch did not exist>}"
          {
            echo "### Presentation branch refreshed"
            echo
            echo "| Field | Value |"
            echo "|---|---|"
            echo "| Strategy | $(md_code "$MODE") (${action}) |"
            echo "| Source ref | $(md_code "$FROM_REF") |"
            echo "| Source commit | $(md_code "$SOURCE_SHA") |"
            echo "| Target branch | $(md_code "$TARGET") |"
            echo "| Previous target commit | $(md_code "$previous") |"
          } >> "${GITHUB_STEP_SUMMARY}"

      # Failing loudly is the point. The cascade previously left a stale
      # presentation branch behind a green release, which is how v2.0.0 went
      # unnoticed for six weeks. A target this workflow cannot write to is a
      # configuration decision the operator has to make, not something to
      # paper over.
      - name: "Refuse: no permitted write path"
        if: steps.strategy.outputs.mode == 'blocked'
        env:
          TARGET: ${{ inputs.target_branch }}
          FROM_REF: ${{ inputs.from_branch }}
          REASON: ${{ steps.strategy.outputs.reason }}
        run: |
          set -euo pipefail
          # Masks $1 for a log line (#492): control characters become '?' and
          # '##[' becomes '#?[', so the value can neither end the line nor open
          # the runner's older '##[command]' syntax in the middle of one.
          shown() { local v="${1//[[:cntrl:]]/?}"; printf '%s' "${v//\#\#\[/#?[}"; }
          # Encode, then wrap, for the step summary (#506): a control character
          # becomes a question mark and an ASCII punctuation character its
          # numeric HTML entity (`@` also gets an empty comment after it, so no
          # e-mail autolink forms), inside <code> (md_code) or <pre> (md_pre,
          # line ends kept). Caller and repository text then renders as
          # text and links nothing.
          md_enc() { local LC_ALL=C; local s="${1//[[:cntrl:]]/?}" c n x; s="${s//$'\xc2'[$'\x80'-$'\x9f']/?}"; s="${s//$'\xe2\x80'[$'\xa8\xa9']/?}"; for n in {33..47} {58..64} {91..96} {123..126}; do printf -v x '%x' "$n"; printf -v c '%b' "\\x$x"; s=${s//"$c"/$'\x01'$n$'\x02'}; done; s=${s//$'\x01'64$'\x02'/$'\x01'64$'\x02\x03'}; s=${s//$'\x01'/'&#'}; s=${s//$'\x02'/';'}; s=${s//$'\x03'/'<!-- -->'}; printf '%s' "$s"; }
          md_code() { printf '<code>%s</code>' "$(md_enc "$1")"; }
          md_pre() { local line; printf '<pre>'; while IFS= read -r line; do md_enc "${line%$'\r'}"; printf '\n'; done <<< "$1"; printf '</pre>\n'; }
          msg="Cannot refresh '${TARGET}' to ${FROM_REF}: ${REASON}. Grant the release App a bypass actor on the target's ruleset, relax the rule, or stop refreshing this branch and point consumers at the release tag instead (issue #414, ADR-001)."
          # msg quotes the caller's target_branch and from_branch; masked so
          # neither can start a workflow command on a new line (#492).
          echo "::error::$(shown "$msg")" >&2
          # The summary repeats msg with both refs encoded (#506); REASON is
          # one of the strategy step's literals and keeps its Markdown.
          {
            echo "### Presentation branch NOT refreshed"
            echo
            echo "Cannot refresh $(md_code "$TARGET") to $(md_code "$FROM_REF"): ${REASON}. Grant the release App a bypass actor on the target's ruleset, relax the rule, or stop refreshing this branch and point consumers at the release tag instead (issue #414, ADR-001)."

            echo "| Field | Value |"

            echo "| Target branch | $(md_code "$TARGET") |"

            echo "| Reason | ${REASON} |"
          } >> "${GITHUB_STEP_SUMMARY}"
