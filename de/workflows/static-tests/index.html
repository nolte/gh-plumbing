    Statische Tests¶

    Führt ein minimales Bündel statischer Analyse bei jedem Pull-Request und bei jedem Push auf den Default-Branch aus und liefert schnelles Feedback ohne externe Dienste.

    • pre-commit, in einer festgelegten Version installiert, führt die in .pre-commit-config.yaml definierten Hooks auf allen Dateien aus; actions/cache, auf einen vollständigen Commit-SHA gepinnt, cacht die Hook-Umgebungen

    Verwendung¶

    .github/workflows/build-static-tests.yaml
    on:
  pull_request:
  push:
    branches: [develop] # durch den eigenen Default-Branch ersetzen

jobs:
  static:
    uses: nolte/gh-plumbing/.github/workflows/reusable-pre-commit.yaml@<tag>

    Erforderlicher Status-Check

    Kombiniere den Workflow mit einer Branch-Protection-Regel, die den Check static / Static CI Tests verlangt — siehe Settings.

    Fork-Pull-Requests brauchen den Trigger pull_request

    Ein Fork pusht nie in das Basis-Repository. Mit einem reinen Push-Trigger meldet sich der erforderliche Check bei einem Pull-Request aus einem Fork nie, und dieser Pull-Request bleibt blockiert. pull_request_target ist keine Alternative. Standardmäßig checkt es den Basis-Branch aus, der erforderliche Check wird also grün, ohne die Änderungen des Pull-Requests zu testen. Checkt man stattdessen den Head des Pull-Requests aus, läuft der Code des Forks mit dem Schreib-Token und den Secrets des Basis-Repositorys. Bei einem Fork-Pull-Request überspringt reusable-trivy.yaml den Upload seines Scan-Berichts in den Security-Tab, weil das Token dort nur Leserechte hat.

    Docker-Hub-Rate-Limits¶

    Ein Hook mit language: docker_image zieht sein Image bei jedem Lauf, und pre-commit kann es nicht cachen: Diese Sprache setzt ENVIRONMENT_DIR = None mit install_environment = no_install, das Image bleibt also im Store des Docker-Daemons und landet nie unter ~/.cache/pre-commit — dem einzigen Pfad, den dieser Workflow an actions/cache übergibt.

    Ein anonymer Pull zählt gegen ein Budget, das an der Quell-IP hängt, und GitHub-gehostete Runner teilen sich ihre Ausgangsadressen plattformweit. Die Lane verbraucht damit ein Budget, das jedes andere Repository im selben Runner-Netz ebenfalls verbraucht — eine Rate-Limit-Ablehnung kann einen erforderlichen Check also aus einem Grund rot färben, der nichts mit dem Diff zu tun hat.

    Zwei optionale Parameter verschieben die Zählung auf ein Konto-Budget:

    Parameter Art Default Zweck
    dockerhub-username Input "" Docker-Hub-Kontoname. Ein Benutzername ist nicht geheim, deshalb reist er als Input. Leer überspringt den Login-Schritt.
    dockerhub-token Secret nicht gesetzt Docker-Hub-Personal-Access-Token zu diesem Konto. Es muss den Scope „Public Repo Read-only“ haben, weil pre-commit-Hooks im selben Job es lesen können.

    Das Token gehört zu einer eigenen Docker ID, die nur die CI nutzt (ein Bot-Konto), nicht zu einer persönlichen, und bekommt ein Ablaufdatum und regelmäßige Rotation. Da Hook-Code es lesen kann, verbraucht ein Leck dann nur das Pull-Kontingent dieses Kontos und legt keine anderswo genutzte Identität offen. Aus demselben Grund persistiert der Workflow das Checkout-Token nicht (persist-credentials: false). Ein Hook, der von origin fetcht, funktioniert deshalb nur in einem öffentlichen Repository, und ein privater Aufrufer braucht einen eigenen Workflow.

    .github/workflows/build-static-tests.yaml
    jobs:
  static:
    uses: nolte/gh-plumbing/.github/workflows/reusable-pre-commit.yaml@<tag>
    with:
      dockerhub-username: ${{ vars.DOCKERHUB_USERNAME }}
    secrets:
      dockerhub-token: ${{ secrets.DOCKERHUB_TOKEN }}

    Beide Parameter sind optional

    Ein Aufrufer, der keinen von beiden übergibt, läuft exakt so wie vor ihrer Einführung: Der Login-Schritt wird übersprungen, die Pulls bleiben anonym. Ein Repository, dessen .pre-commit-config.yaml keinen language: docker_image-Hook deklariert, gewinnt nichts durch das Setzen.

    Ein defektes Credential degradiert, es lässt den Lauf nicht scheitern

    Der Login-Schritt trägt continue-on-error. Ein abgelaufenes Token, ein Token, das einem Fork-Pull-Request vorenthalten wird, oder ein Benutzername ohne Token fallen alle auf anonyme Pulls zurück und erzeugen eine Warning-Annotation. Hart zu scheitern würde die erforderliche Lane bei jedem Pull-Request rot färben — schlimmer als das Rate-Limit, das der Login vermeidet. Das Run-Log nennt immer den verwendeten Modus.

    Warum kein GHCR-Mirror?

    Die Hooks auf einen Mirror zu zeigen, braucht ein entry:-Override und entkoppelt damit den Image-Tag vom rev: des Hooks. Genau dieses rev: beobachtet die Update-Automatisierung — der Mirror würde unbeobachtet altern.

    Zentrale Konfiguration¶

    .github/workflows/reusable-pre-commit.yaml
    name: Reusable — Pre-Commit

# Runs the consumer's `.pre-commit-config.yaml`. Most consumers put this job
# behind the `static / Static CI Tests` required check, so anything that can
# redden it for a reason unrelated to the diff is a defect in this file, not in
# the pull request that happens to be unlucky.
#
# One such reason is Docker Hub rate limiting. A hook declared with
# `language: docker_image` pulls its image on every run, and pre-commit cannot
# cache it -- `pre_commit/languages/docker_image.py` sets `ENVIRONMENT_DIR = None`
# with `install_environment = no_install`, so the image lives only in the Docker
# daemon's store and never lands under `~/.cache/pre-commit`, which is the only
# path this workflow hands to `actions/cache`. There is nothing for that cache
# to hold. Measured on nolte/kamerplanter#1321, whose two hooks
# (`rhysd/actionlint`, `koalaman/shellcheck-precommit`) return
# `ratelimit-limit: 100;w=3600` with no publisher exemption.
#
# The decisive property of an anonymous pull is not the number but the bucket:
# it is counted per source IP, and GitHub-hosted runners share egress addresses
# across the whole platform. So the budget this lane spends is shared with every
# other repository that happens to land on the same runner network, and no
# amount of restraint here protects it. Authenticating moves the count to a
# per-account bucket that only this organization draws on.
#
# `docker/login-action` writes `~/.docker/config.json` on the runner, and
# pre-commit's docker_image language shells out to `docker run` against the same
# host daemon (`pre_commit/languages/docker.py:docker_cmd`), so the credentials
# apply to the hook pulls without either side knowing about the other.
#
# Deliberately NOT done: mirroring the images to GHCR and pointing the hooks at
# the mirror through an `entry:` override. That decouples the image tag from the
# hook's `rev:`, which is the pin Renovate actually watches; the mirror would
# then age unwatched. See nolte/kamerplanter#1321.
#
# Deliberately NOT done: pre-pulling the images and shuttling them through
# `actions/cache` with `docker save`/`docker load`. It needs no credentials,
# which is genuinely attractive for a shared reusable, but a consumer's
# `.pre-commit-config.yaml` names only `repo:`/`rev:`/`id:` -- the image
# reference lives in the *hook* repository's `.pre-commit-hooks.yaml`, so this
# workflow would have to clone every hook repo at its `rev` to learn what to
# pull, duplicating what `pre-commit install-hooks` already does. And on a cache
# miss (a `rev` bump, a 7-day eviction, a feature branch that cannot read
# another branch's cache) the pull is anonymous again, so it lowers the
# frequency of the failure without removing it. Authentication removes it.

on:
  workflow_call:
    inputs:
      dockerhub-username:
        description: |
          Docker Hub account name used to authenticate the image pulls made by
          `language: docker_image` pre-commit hooks. A username is not secret --
          it appears in every image reference -- so it travels as an input, and
          only its token half travels as a secret. This mirrors the
          `app-id` input / `app-private-key` secret split in
          `reusable-branch-protection-audit.yaml`, and it is also what makes the
          gate expressible: the `secrets` context is not available in a step's
          `if:`, so a secret alone cannot decide whether a step runs.

          OPTIONAL. Empty -- the default, and what every consumer that has not
          changed its call gets -- skips the login step and pulls anonymously,
          which is exactly the behaviour this workflow had before the input
          existed. Consumers whose `.pre-commit-config.yaml` declares no
          `language: docker_image` hook have nothing to gain by setting it.
        required: false
        type: string
        default: ""
    secrets:
      dockerhub-token:
        description: |
          Docker Hub personal access token matching `inputs.dockerhub-username`.
          It MUST be created with the "Public Repo Read-only" access scope.
          Nothing in this workflow pushes, and a wider scope is not merely
          unnecessary but exposed: the hook environments are installed before
          the login, but the hooks that `pre-commit run` then executes in every
          non-docker language (e.g. python, node, golang, system, script) run on
          the host in the same job and can read `~/.docker/config.json` while
          they run. The post-step logout of `docker/login-action` does not
          revoke a token that was already read, and with passwordless sudo a
          hook can also read it from runner memory. The scope is therefore the
          only control: anything broader than public read-only would be handed
          to third-party hook code. Required in practice whenever
          `dockerhub-username` is set, but declared optional so that a caller
          which sets neither still resolves.
        required: false

# Explicit permissions per spec/project/github-actions-best-practices §B:
# workflow level is the minimum, write scopes are granted per job.
permissions:
  contents: read # checkout + pre-commit; the hooks never push


jobs:
  static:
    name: "Static CI Tests"
    runs-on: ubuntu-latest
    steps:
      - name: Checkout sources
        uses: actions/checkout@d23441a48e516b6c34aea4fa41551a30e30af803 # v6.1.0
        with:
          # Not persisted, like the consumer checkout in
          # `reusable-docs-freshness.yaml` (the remaining checkouts follow in
          # #471). `pre-commit run` executes hook code from third-party
          # repositories later in this job, and a persisted token -- in v6 a
          # file under `$RUNNER_TEMP` that `.git/config` includes -- is
          # readable by any process in the job.
          # This removes the unprivileged path, a file any process can read; it
          # is not a boundary against hostile hook code. Hooks run with
          # passwordless sudo on GitHub-hosted runners and can read the runner
          # process's memory, so the real limit on the job token is
          # `permissions: contents: read`.
          # Nothing here needs authenticated git: the job holds `contents: read`
          # only, and pre-commit clones the hook repositories into its own cache
          # anonymously. A future private consumer whose hook fetches `origin`
          # would need a workflow of its own rather than a token left lying here.
          persist-credentials: false

      - uses: actions/setup-python@ece7cb06caefa5fff74198d8649806c4678c61a1 # v6.3.0
        with:
          # Concrete rather than '3.x', matching the other reusables and
          # .tool-versions. This workflow sits behind `static / Static CI Tests`,
          # which is the one required check most consumers enforce, so a
          # floating interpreter here can turn a green pipeline red with no
          # commit behind it. #400 pinned the input defaults elsewhere and
          # missed this hardcoded one.
          python-version: '3.14'

      # The three steps below and `Run pre-commit` at the end replace
      # `pre-commit/action` v3.0.1, a composite action whose own cache step
      # references `actions/cache@v4` by tag. The repository setting
      # `sha_pinning_required` checks nested references as well, so a single
      # tag two levels down fails the whole job. Inlining the composite keeps
      # its behaviour and puts every `uses:` under this file's control, where it
      # is pinned to a full commit SHA. The hook-environment install and the
      # Docker Hub login sit between the cache and the run; see the next step.
      - name: Install pre-commit
        # Inline rather than `-r requirements-dev.txt`: this reusable runs in
        # the consumer's checkout, where no gh-plumbing requirements file
        # exists. Same version as `requirements-dev.txt`. Renovate does not
        # track this inline pin yet -- see #467.
        run: |
          set -euo pipefail
          python -m pip install pre-commit==4.7.0

      - name: List installed Python packages
        # Kept from the composite action, so the log still records the exact
        # resolved versions consumers have been able to read there.
        run: |
          set -euo pipefail
          python -m pip freeze --local

      - name: Cache pre-commit hook environments
        uses: actions/cache@0057852bfaa89a56745cba8c7296529d2fc39830 # v4.3.0
        with:
          path: ~/.cache/pre-commit
          # Copied verbatim from `pre-commit/action` v3.0.1, prefix and
          # separators included, so caches consumers already built under the
          # composite action keep hitting after the switch.
          key: pre-commit-3|${{ env.pythonLocation }}|${{ hashFiles('.pre-commit-config.yaml') }}

      - name: Install hook environments
        # Every hook environment -- the pip/npm/... install of each third-party
        # hook repository -- is built here, as are the cache restore and the
        # pip install above, all before any Docker Hub credential exists on the
        # runner. The login below writes `~/.docker/config.json` only for
        # `pre-commit run`, which needs it because `language: docker_image`
        # hooks pull lazily through `docker run`. Accepted trade-off: hooks with
        # `language: docker` build their image in this step, so their
        # base-image pulls stay anonymous and count against the shared per-IP
        # rate limit. Unlike `pre-commit run`, which installs only the hooks of
        # the stage it runs, `install-hooks` builds the environments of every
        # stage -- `manual` and `commit-msg` hooks included -- so a consumer
        # whose non-default-stage hook cannot be installed on this runner fails
        # here, although `pre-commit run` would never execute that hook.
        run: |
          set -euo pipefail
          pre-commit install-hooks

      - name: Log in to Docker Hub
        id: dockerhub-login
        # Skipped, not failed, when the caller supplies nothing. An anonymous
        # pull is the status quo, and a reusable workflow that started demanding
        # a new secret would break every consumer on its next call.
        if: ${{ inputs.dockerhub-username != '' }}
        # continue-on-error, unlike the App-token step in
        # `reusable-branch-protection-audit.yaml`, where a degraded token makes
        # every repository look unprotected and a wrong answer beats no answer.
        # Here the fallback is not degraded, it is the previous behaviour: an
        # expired token, a token withheld from a fork's pull request, or a
        # username set without one all land back on anonymous pulls. Hard-failing
        # instead would redden the required lane on every pull request in the
        # consuming repository -- strictly worse than the rate limit this step
        # exists to avoid. The next step says out loud which mode was used.
        continue-on-error: true
        uses: docker/login-action@c94ce9fb468520275223c153574b00df6fe4bcc9 # v3.7.0
        with:
          username: ${{ inputs.dockerhub-username }}
          password: ${{ secrets.dockerhub-token }}

      - name: Report the registry mode this run will use
        # Always runs, including after a failed login, so the log states the
        # mode rather than leaving it to be inferred from a step's colour.
        env:
          LOGIN_OUTCOME: ${{ steps.dockerhub-login.outcome }}
        run: |
          set -euo pipefail
          case "${LOGIN_OUTCOME}" in
            success)
              echo "Docker Hub: authenticated pulls (per-account rate limit)."
              ;;
            skipped)
              echo "Docker Hub: anonymous pulls (per-IP rate limit shared with" \
                   "other runners). Set the 'dockerhub-username' input and the" \
                   "'dockerhub-token' secret to authenticate."
              ;;
            *)
              echo "::warning title=Docker Hub login failed::Continuing with" \
                   "anonymous pulls, which are rate limited per source IP." \
                   "Check the 'dockerhub-username' input and the" \
                   "'dockerhub-token' secret of the calling workflow."
              ;;
          esac

      - name: Run pre-commit
        run: |
          set -euo pipefail
          pre-commit run --show-diff-on-failure --color=always --all-files
